# Reaudit the qualified-resource choice before confirmation

`unlock_resource_confirmation.py` releases the original confirmation panel after the complete qualified-resource DEV comparison selects a learned candidate. It keeps the original generation executor and uses a separately frozen offline auditor with unchanged task-audit, statistics and selection helpers. The [strict single-slot access command](confirmation-access.md) remains available for the original dispatcher.

The qualified policy's exact path and hash must match both the explicit dispatch plan and immutable choice. The independent auditor rechecks the complete twenty-two-condition study, every original task journal and fresh test, raw physical fingerprints, per-condition slot observations and the numerical resource qualification. Its new choice must be byte-identical to the original. The existing access builder then binds the selected native/cache/conversion/adapter bytes before parsing the forty-nine original sanitized confirmation tasks.

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH="$PWD/src" .harness-venv/bin/python \
  scripts/unlock_resource_confirmation.py \
  --dev-grid /path/to/completed/resource-dispatch \
  --dev-executor /path/to/original-generation-executor \
  --dev-executor-commit ORIGINAL_GENERATION_COMMIT \
  --resource-auditor /path/to/frozen-resource-comparison \
  --resource-auditor-commit EXACT_OFFLINE_AUDITOR_COMMIT \
  --resource-supplement /path/to/qualified/resource.json \
  --packets /path/to/measured-conversions --out runs/resource-confirmation-access
```

`--plan-only` hashes source and manifest metadata without parsing confirmation tasks, qualifying a resource policy, or launching the offline audit. Actual mode first requires the completed DEV choice. The current incomplete grid is rejected before the confirmation parser or offline child process is called.

The access plan's existing `dev_executor_commit` field names the actual offline auditor, matching `offline_dev_auditor_executor_commit` in the receipt. `generation_executor` and `generation_executor_commit` separately preserve the original model execution source. Both source trees are pinned. This retains the existing protected loader format: the loader itself and three protected execution entry points are unchanged. The choice hash binds the resource comparison and its raw evidence.

The [CPU preparation report](../reports/resource-confirmation-access-preparation-v1.json) records isolated binding controls, loader compatibility, a declaration against actual frozen software, and rejection of the real unfinished grid with zero confirmation parser calls and zero offline children. It establishes no genuine access release, hardware qualification, confirmation result or model score. An actual qualified dispatcher, completed model study and independent reaudit remain required.
