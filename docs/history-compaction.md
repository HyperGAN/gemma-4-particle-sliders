# Official history compaction

The authenticated harness README and the Kaggle staff [starter notebook](https://www.kaggle.com/code/ryanholbrook/getting-started-gemma-4-developer-agent) configure ADK event compaction at 14,336 prompt tokens, keeping five recent events, with a 15-invocation sliding interval and overlap of two. They also configure context caching with a 2,048-token minimum, 1,800-second TTL and interval of ten.

Earlier local runs constructed `EvalConfig` with neither option. The installed `swegemma` runner passes those options to `App` only when provided. The old trajectories remain valid matched research attempts under their explicit budgets, but they do not establish parity with the official history-management setup. Their failures, tests, context-exhaustion proofs and zero-target outcomes retain their original identities. No old result is promoted to a compacted run.

New direct trajectory commands default to `official-compaction-v2`. Collection plans declare their history profile and settings explicitly; legacy plans use `uncompacted-v1`. Each collector passes that choice explicitly to the agent runner, and all four arms must match it. The contract, captured outcome and verifier receipt bind the profile. Historical executors retain their frozen checkouts.

The host uses public `ContextCacheConfig`, `EventsCompactionConfig` and `LlmEventSummarizer` APIs with the starter's values and the same compiled canonical root model. The summarizer's prompt is unchanged. A scoped context variable marks summary transport calls in the request journal. They remain fully recorded and hash-bound but cannot become assistant-decision training targets. A summary tag cannot hide an ordinary system/tool decision. Subsequent assistant targets retain exactly the history actually observed, including any compacted summary; teacher/student differ only by the declared behavioral system instruction.

The first [CPU-only qualification](../reports/history-compaction-controls-v1.json) used a direct ADK agent. The first actual model trial exposed an omitted compiler boundary: the compiler deep-copies the registered model/client, while the v1 summarizer retained the original client. Its independent counter overwrote request zero, then completion capture failed. The run is preserved as a capture error, supplied zero targets, and cannot be repaired into a valid control. It also revealed that summarization must use the compiled model's inherited seed/thinking settings.

The [v2 qualification](../reports/history-compaction-controls-v2.json) now compiles the real baseline artifact before its ADK loop. One task-owned transport/journal survives model cloning. A recording model subclass observes the actual compiled root on its first decision, and the public summarizer uses that same model. The fixture checks inherited seed/thinking controls, all eight decisions and eleven summaries, and subsequent observed summary history. Exclusive file creation also prevents a duplicated counter from overwriting a prior request. The full 69-test CPU suite includes this compiler regression. Synthetic usage metadata triggers the token-threshold mechanism; this is software evidence, never training targets or coding quality.

The old GPU 1 pool closed after four started tasks, retaining their complete outcomes and withdrawing 51 unattempted tasks. Its final `fastapi_13786` quartet supplied zero targets. The suspended scheduler terminated, and its owned server and engine released their GPU memory before a separate native resource probe started. The corrected compacted cohort requires fresh OFF and teacher runs. Model outcomes and official-scoring equivalence remain separate from CPU qualification.
